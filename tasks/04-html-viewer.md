# T-04: Самодостаточный HTML-вьювер

- **Статус:** готово
- **Приоритет:** high
- **Оценка:** S (2–4 дня)
- **Зависимости:** нет
- **Квартал roadmap:** Q1 2027

## Цель

Один HTML-файл, который открывается у любого человека в браузере и
показывает оружие в 3D с орбит-контролами и списком частей. Не нужен
ни Blender, ни установка чего-либо: скинул файл — работает.

```bash
wog-dump build-scene ak47 --viewer
# → runtime/scenes/ak47/viewer.html  (GLB встроен в файл)
```

## Контекст: что уже есть в коде

- `core/scene.py::SceneBuilder.build_scene()` уже пишет GLB и
  `scene.json` (манифест со списками parts/field_strip, счётчики
  skipped-объектов).
- Имена glTF-узлов соответствуют GameObject-ам — по ним можно строить
  список частей в UI.
- `src/wog_dump/resources/` — место для шаблонов (там лежит
  `blender_setup.py`), включаются в пакет через hatch-конфиг.

## Техническое решение

- Вьювер на **three.js** (модуль ES + `GLTFLoader` + `OrbitControls`).
  Код three.js кладётся в `resources/viewer/` вендор-копией (фиксированная
  версия, зафиксировать в комментарии) — без CDN, файл работает офлайн.
- GLB встраивается в HTML как base64-data-URI (или через `<script
  type="application/octet-stream">`-блок; выбрать по размеру: data-URI
  проще, но +33% размера; blob из вложенного `<script>`-текста — компактнее.
  Решение зафиксировать по факту замера на самом большом оружии).
- Альтернатива `--viewer-link`: HTML + GLB рядом, GLB грузится fetch-ом —
  для больших сцен (обе опции в задаче).

## Требования

### Функциональные

- `build-scene --viewer` дополнительно к обычному выводу пишет
  `viewer.html` в папку сцены.
- Возможности UI (минимум):
  - орбит-вращение, зум, панорама (OrbitControls);
  - список частей из `scene.json` (parts + field_strip); клик по имени —
    подсветка узла (emissive-подсветка) и фокус камеры на нём;
  - счётчик треугольников и частей в шапке;
  - кнопка «wireframe» и «автоповорот»;
  - тёмная/светлая тема по `prefers-color-scheme`.
- Никаких внешних запросов при открытии файла (проверить: ни одного
  URL за пределами data:-URI).
- Работает в Chrome/Firefox/Safari последних двух мажорных версий.

### Нефункциональные

- Размер: viewer.html ≤ размер GLB × 1.5 (замер зафиксировать в тесте
  как предупреждение, не как провал).
- Генерация — чистая функция `render_viewer_html(glb: bytes, manifest: dict)
  -> str` в новом `core/viewer.py`; шаблонизатор — `string.Template`
  из stdlib ( Jinja не тянуть ради одного файла).

## План реализации

1. Прототип вёрстки/JS отдельно (`resources/viewer/viewer.js` +
   `template.html`) — проверить руками на ak47.glb.
2. Вендор three.js зафиксированной версии в `resources/viewer/vendor/`
   (минифицированные модули), LICENSE-файл three.js рядом (MIT).
3. `core/viewer.py::render_viewer_html()` — сборка строки.
4. Флаг `--viewer` в `cli/scene.py`; опция `--viewer-link` для
   двухфайловой версии.
5. README: раздел с скриншотом.

## Критерии приёмки

- [ ] `viewer.html` для ak47 открывается двойным кликом из файлового
      менеджера (file:// без сервера) и рендерит модель
- [ ] Клик по части в списке подсвечивает её в 3D
- [ ] Открытие файла не делает сетевых запросов (проверка: DevTools
      Network пуст, или тестом — grep по http:// и https:// в HTML,
      кроме комментариев)
- [ ] `--viewer` не влияет на остальные выходные файлы сцены
- [ ] Тест: `render_viewer_html()` на фикстуре возвращает валидный HTML
      (парс через html.parser stdlib), содержит base64-GLB и манифест

## Тесты

- `tests/unit/test_viewer.py`: генерация HTML на маленькой фикстуре
  GLB (несколько сотен байт), проверка вложенных данных и списка частей;
  отсутствие внешних URL.
- Ручной чек-лист браузеров — зафиксировать в PR.

## Риски и открытые вопросы

- Большие GLB (100+ МБ) могут сделать data-URI неповоротливым — для
  них `--viewer-link` (основной путь); порог предупреждения — 50 МБ.
- Вендор three.js в репо — ~700 КБ минифицированного; принять как
  осознанную цену офлайн-работы (альтернатива CDN — отвергнута:
  файл должен жить годами без интернета).
