# T-05: Превью-рендеры через headless Blender

- **Статус:** готово
- **Приоритет:** medium
- **Оценка:** M
- **Зависимости:** нет
- **Квартал roadmap:** Q1 2027

## Цель

Команда `render` превращает готовую GLB-сцену в набор PNG-превью
(turntable: вид с 8 ракурсов вокруг оружия). Превью нужны для каталога
(T-07 его использует опционально), README, релизных анонсов и быстрой
проверки «что я вообще скачал» без запуска Blender руками.

```bash
wog-dump render ak47                      # 8 PNG в runtime/scenes/ak47/previews/
wog-dump render ak47 m4a1 --angles 12 --size 1600
wog-dump render --all                     # всё, для чего есть сцены
```

## Контекст: что уже есть в коде

- `runtime/scenes/<weapon>/<weapon>.glb` — готовые сцены с камерой и
  студийным светом (строит `core/scene.py`), т.е. источник данных уже
  существует; задача — только рендер поверх него.
- `resources/blender_setup.py` — шаблон генерируемого скрипта: проект
  уже умеет готовить python-скрипты для headless Blender
  (`blender --background --python ...`).
- В сценах уже настроены студийный свет и камера (`_add_studio_rig` в
  `core/scene.py:598`) — рендер-скрипт может использовать их как есть,
  вращая камеру вокруг цели.

## Требования

### Функциональные

- Новая команда `wog-dump render <weapons...>` (+ `--all`), рендерит
  N ракурсов равномерно по кругу вокруг оружия (дефолт 8).
- Параметры: `--angles N`, `--size PX` (квадрат, дефолт 1280),
  `--format {png,jpg,webp}`, `--elevation DEG` (угол возвышения камеры,
  дефолт 15°).
- Вывод: `runtime/scenes/<weapon>/previews/ak47_01.png ... 08.png` +
  `preview.gif` (простая GIF-склейка тех же кадров, Pillow уже в deps).
- Определение Blender: `WOG_BLENDER_PATH` (config/env), иначе
  `shutil.which("blender")`, иначе — ошибка с инструкцией по установке
  и exit code 1. Версия Blender: любая 3.6+ / 4.x.
- `wog-dump info` показывает найденный путь к Blender (в разделе про
  окружение), если рендер-команда доступна.
- Если сцены для оружия нет — понятная подсказка «сначала build-scene».

### Нефункциональные

- Рендер — временный python-скрипт во временной папке (tempfile), не
  в `runtime/`; чистится после запуска даже при ошибке.
- Последовательные вызовы Blender по одному оружию (не параллелить:
  Blender сам многопоточный); `--max-threads` не трогает Blender.
- Прозрачный фон PNG (`film_transparent`) — превью удобно вставлять
  в README/каталог.
- Идемпотентность: повторный `render` перезаписывает превью без
  предупреждений (это явный кэш, не пользовательские данные).

## План реализации

1. `core/render.py::RenderManager`: поиск Blender, генерация скрипта
   (шаблон в `resources/render_turntable.py`), запуск через
   `subprocess.run`, парсинг stderr Blender на предмет ошибок,
   код возврата → `RenderError`.
2. Blender-скрипт: импорт GLB, использование камеры/света сцены либо
   собственный риг (если в GLB нет камеры — fallback: создать
   camera+light, вписать модель в кадр по bounding box), цикл по
   углам: поворот камеры вокруг центра, рендер `scene.render`.
3. GIF-склейка: `Pillow` (в deps уже есть).
4. CLI `cli/render.py`, регистрация в `cli/main.py`, покрытие в
   `cli/errors.py`.
5. `info`: показ пути Blender.

## Критерии приёмки

- [ ] `wog-dump render ak47` при установленном Blender даёт 8 PNG
      равномерных ракурсов + GIF
- [ ] Без Blender: понятная ошибка в одну строку, exit 1
- [ ] Превью оружия с прозрачным фоном, модель вписана в кадр целиком
      (нет обрезанных краёв) минимум для 3 разных оружий
- [ ] Повторный запуск перезаписывает файлы без ошибок
- [ ] Юнит-тесты: генерация скрипта (фиксированные вставки: путь GLB,
      углы, размер), поиск Blender (mock `shutil.which`), обработка
      ненулевого кода возврата Blender

## Тесты

- `tests/unit/test_render.py`: mock subprocess; проверка содержимого
  сгенерированного скрипта (подстановки), обработка ошибок запуска.
- Integration (skip без Blender в PATH): рендер маленькой тестовой GLB
  (сгенерировать через GLBWriter на синтетическом кубе) → 8 файлов
  ненулевого размера.

## Риски и открытые вопросы

- У WSL2 (окружение автора) Blender может быть Windows-бинарём —
  поддержать путь к .exe: проверять исполняемость и запускать как есть;
  отметить в доке, что рендер работает и с Windows-Blender из WSL.
- Разные версии Blender дают разный видовой вывод — зафиксировать
  в README, что превью не претендуют на идентичность между версиями.
