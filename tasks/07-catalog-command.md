# T-07: Команда catalog

- **Статус:** готово
- **Приоритет:** high
- **Оценка:** S (2–3 дня)
- **Зависимости:** нет
- **Квартал roadmap:** Q2 2027

## Цель

Сейчас пользователь не имеет способа ответить на вопрос «что вообще
есть и что уже скачано» кроме как `ls runtime/`. Команда `catalog`
даёт таблицу всего оружия с поэтапным статусом pipeline, поиском,
сортировкой и машинным JSON-выводом (JSON-схема из этой задачи —
стабильный интерфейс для T-21 Blender-аддона).

```bash
wog-dump catalog                       # таблица всего оружия
wog-dump catalog --filter ak           # поиск по подстроке
wog-dump catalog --status scene        # только то, для чего есть сцены
wog-dump catalog --sort size --json    # JSON для инструментов
```

## Контекст: что уже есть в коде

- `core/database.py::WOGDatabase.get_weapons()` — список имён оружия;
  `get_keys()` — по каким есть ключи; `get_stats()` — агрегаты.
- Структура `runtime/`: `encrypted/`, `decrypted/`, `unpacked/`,
  `scenes/<weapon>/` — статус стадий определяется файлами на диске.
- Rich уже в зависимостях (прогресс/логгинг) — таблицы Rich бесплатно.
- `cli/info.py` — пример команды-отчёта (статус, не список).

## Требования

### Функциональные

- Колонки таблицы: name, key (есть/нет), downloaded, decrypted,
  unpacked, scene (стадии — ✓/—), size (сумма encrypted+decrypted
  по оружию, человекочитаемо), previews (✓ если есть папка previews/
  от T-05 — опциональная колонка, показывается всегда, просто пустая
  без T-05).
- Фильтры: `--filter <substr>` (case-insensitive по имени),
  `--status {key,downloaded,decrypted,unpacked,scene}` — оставить
  только строки, прошедшие стадию.
- Сортировка: `--sort {name,size,status}`, дефолт name; `--reverse`.
- `--limit N` для больших каталогов (288+ оружий).
- `--json`: стабильная схема (см. ниже), одна запись на оружие,
  поля всегда присутствуют (null вместо пропусков).
- Статус «scene» = существует `runtime/scenes/<weapon>/<weapon>.glb`.

### JSON-схема (стабильный контракт, версия 1)

```json
{
  "schema": "wog-dump.catalog/1",
  "count": 288,
  "weapons": [
    {
      "name": "ak47",
      "has_key": true,
      "downloaded": true,
      "decrypted": false,
      "unpacked": false,
      "scene": false,
      "previews": false,
      "size_bytes": 12345678
    }
  ]
}
```

Поле `schema` — для будущих изменений; потребители (T-21) обязаны
проверять его. Любое изменение полей — только через новое значение
`schema` (добавление полей допустимо в той же версии).

### Нефункциональные

- Сканирование диска — один проход по 4 директориям, не stat на
  каждое оружие × стадии (перечисление directory listing, сравнение
  имён). На полном каталоге — < 1 сек.
- Работа без сети и без логина: catalog читает только локальное
  (БД + файловая система).
- Пустая БД (никогда не было download-weapons) — дружелюбное
  сообщение «run wog-dump download-weapons first», exit 0.

## План реализации

1. `core/catalog.py::build_catalog(config) -> list[WeaponEntry]`:
   чтение БД + один проход листингов директорий; чистая функция без
   Click/Rich — тестируемая напрямую.
2. CLI `cli/catalog.py`: таблица Rich, фильтры/сортировка/JSON.
3. Регистрация команды, покрытие ошибок в `cli/errors.py`.
4. Справка в README (раздел Usage).

## Критерии приёмки

- [ ] Таблица на полном каталоге рендерится < 1 сек, не ломает
      терминал при 288+ строках (Rich сам листает; проверить)
- [ ] Все фильтры и сортировки работают на смешанном локальном
      состоянии (часть оружия скачана, часть нет)
- [ ] `--json` соответствует схеме `/1`; поле size_bytes — сумма
      файлов оружия, проверена вручную на одном примере
- [ ] Без данных — понятное сообщение, exit 0
- [ ] Юнит-тесты build_catalog на синтетическом дереве runtime/
      (tmp_path с фикстурами файлов)

## Тесты

- `tests/unit/test_catalog.py`: фикстуры файловой системы через
  `tmp_path` (encrypted/decrypted/unpacked/scenes с несколькими
  оружиями в разных стадиях), проверка статусов, size, фильтрации.
- CLI-тест: `--json` через CliRunner, сравнение со схемой (ключи
  и типы полей).

## Риски и открытые вопросы

- Расхождение имён файлов и имён из БД (префиксы вроде `w_`) —
  правила маппинга собрать эмпирически и зафиксировать в
  `core/catalog.py` константой-нормализатором с тестами.
