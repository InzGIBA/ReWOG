# T-13: Проверка совместимости протокола (protocol probe)

- **Статус:** не начата
- **Приоритет:** high
- **Оценка:** M
- **Зависимости:** нет
- **Квартал roadmap:** Q3 2027

## Цель

Игра обновляется, протокол `query2026` дрейфует, и сейчас это
обнаруживается как «непонятная ошибка логина» или «No weapon list
found» (как было в v2.6.1). Дать пользователю и разработчику команду,
которая за минуту отвечает на вопрос «у меня сломалось или у игры
обновилось?», и дать проекту страховочную сетку golden-фикстуров
протокола.

```bash
wog-dump info --protocol-probe     # таблица проверок + вердикт
```

## Контекст: что уже есть в коде

- `core/api.py::WOGApiClient` — BZ2-over-HTTP query-клиент:
  `call(params)`, `compress_request`, `decompress_response`,
  `build_common_params`; endpoint `query2026.php`, поля game_version
  и т.д.
- `core/auth.py::AuthManager` — логин/сессия/шард eu1/us3...
  (v2.7.1: следование result=777 redirect).
- `core/keys.py::KeyManager` — query=3 sync-запросы (дешёвая
  аутентифицированная проверка).
- `core/download.py::download_weapon_list()` — доступность
  data-сервера и парс `new_banners` (v2.6.1: формат менялся —
  живой пример дрейфа).
- `docs/mitm-capture.md` — инструкция снятия капчура; на неё
  будут ссылаться подсказки probe.

## Требования

### Функциональные

`wog-dump info --protocol-probe` выполняет каскад проверок и
выводит таблицу (проверка / результат / деталь):

1. **DNS+TCP+TLS** до api-хоста и data-хоста — сетевая
   достижаемость (без этого остальные бессмысленны).
2. **Анонимный запрос** к query-endpoint (ожидаемая ошибка без
   сессии, но отвечающая) — endpoint жив, версия протокола не
   проверяется.
3. **Аутентифицированный query=3** с сохранённой сессией (если
   логина нет — проверка пропущена со статусом SKIP и подсказкой
   `wog-dump login`).
4. **Weapon-list доступность**: HEAD/GET catalog-файла на
   data-сервере.
5. **Клиентские версии**: `WOG_GAME_VERSION`/`UNITY_VERSION` из
   конфига против минимально известной рабочей — предупреждение
   о возможном устаревании (сравнение с константой в коде).

Вердикты: `OK` / `FAIL(причина)` / `SKIP(причина)` / `WARN`.
Итог: «Протокол совместим» либо «Обнаружен дрейф протокола:
<проверка>» + конкретные следующие шаги (mitm-capture.md,
issue-шаблон «Protocol drift» с результатами probe — приложить
вывод `--protocol-probe --json`).

- `--json`: машиночитаемый отчёт (schema `wog-dump.probe/1`).
- Exit codes: 0 — всё OK/WARN; 2 — обнаружен FAIL (для CI).

### Golden-фикстуры протокола (страховочная сетка)

- `tests/fixtures/protocol/` — захваченные (и очищенные от секретов!)
  ответы сервера: login OK, login 777-redirect, query=3 sync,
  оружие-лист `new_banners` (оба формата из v2.6.1).
- Юнит-тесты парсеров (`core/api.py`, `core/auth.py`,
  `core/unpack.py::WeaponListProcessor`) гоняются на фикстурах:
  любое изменение формата сервера, воспроизведённое капчей,
  обнаруживается локально до релиза.
- Скрипт `scripts/refresh_protocol_fixtures.py`: интерактивно
  снимает свежие ответы (требует логина, помечен как
  ручной инструмент мейнтейнера; секреты вырезаются автоматически:
  скрипт обязан фейлить CI, если в fixture-файле появились строки
  `pass=`/`hash=`/`session=` — проверка-гвард в тесте).

## План реализации

1. `core/probe.py::ProtocolProbe`: список проверок как маленькие
   функции `check(client, config) -> ProbeResult`; переиспользуют
   существующие клиенты, ничего нового про протокол не изобретают.
2. Вывод в `cli/info.py` (`--protocol-probe`, `--json`), exit codes.
3. Фикстуры + тесты-гварды секретов.
4. `scripts/refresh_protocol_fixtures.py`.
5. Issue-шаблон `.github/ISSUE_TEMPLATE/protocol_drift.md`
   (вывод probe + версия + дата).
6. README/FAQ: «Всё сломалось после обновления игры → прогоните
   probe».

## Критерии приёмки

- [ ] На живом API (логин в БД): все проверки OK, exit 0
- [ ] Без логина: SKIP с подсказкой, остальные проверки осмысленны
- [ ] Симуляция дрейфа (мок-сервер с изменённым форматом): probe
      даёт FAIL по адресу и ссылку на капчу-инструкцию, exit 2
- [ ] Фикстуры в тестах: парсеры покрыты, гвард секретов работает
      (тест с подсунутым `pass=` в fixture фейлится)
- [ ] README/FAQ обновлены

## Тесты

- `tests/unit/test_probe.py`: каждая проверка на моках клиентов
  (OK/FAIL/SKIP), каскад останавливается при сетевой
  недоступности.
- `tests/unit/test_protocol_fixtures.py`: парсеры против
  фикстуров + гвард секретов.

## Риски и открытые вопросы

- Анонимный запрос к query-API: проверить на капче, какой ответ
  безопасно считать «endpoint жив» (не блокирует ли частые
  анонимные запросы) — при сомнении проверку сделать опциональной
  (`--deep`).
