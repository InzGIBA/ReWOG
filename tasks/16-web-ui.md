# T-16: Локальный веб-интерфейс

- **Статус:** не начата
- **Приоритет:** medium
- **Оценка:** L (3+ недели)
- **Зависимости:** нет
- **Квартал roadmap:** Q2–Q3 2027

## Цель

Локальный веб-UI поверх тех же core-модулей: страница-каталог со
статусами и превью, страница оружия с 3D-просмотром GLB, кнопки
запуска стадий pipeline с живым логом. CLI остаётся единственным
источником правды — UI его оборачивает, ничего не дублирует.

```bash
wog-dump serve                 # http://127.0.0.1:8765
wog-dump serve --no-browser --port 9000
```

## Контекст: что уже есть в коде

- `core/` — вся логика переиспользуется как библиотека:
  `WOGDatabase` (каталог, статусы), `DownloadManager`,
  `AssetDecryptor`, `AssetUnpacker`, `SceneBuilder`.
- `runtime/scenes/<weapon>/` — GLB для three.js-просмотра (готовые
  файлы, рендер в браузере).
- README «Using as a Python library» — курс на использование core
  без CLI подтверждён.

## Решение по архитектуре (обоснование)

- Backend: FastAPI + uvicorn, extra `wog-dump[web]` (тяжёлые
  зависимости не тащим в ядро).
- Frontend: без npm-сборки — статические файлы (одна страница,
  htmx или vanilla JS + three.js с CDN; three.js локально в
  static/, по решению T-04 вендор-копия уже может лежать в
  resources/viewer/ — переиспользовать её файл, не добавлять вторую
  копию; если T-04 ещё не сделана, положить свою).
- Запуск стадий: subprocess `wog-dump <command> ...` (изоляция
  процесса, свежая конфигурация, ровно то же поведение, что в
  терминале), а не вызовы core в процессе сервера. Живой вывод —
  чтение stdout/stderr подпроцесса, стриминг через SSE.

## Требования

### Функциональные

- **Каталог**: таблица оружия (данные — прямые запросы
  `WOGDatabase` + листинг runtime/ по образцу статусов сцен);
  колонки как в T-07 (задача НЕ зависит от T-07: списки/статусы
  собираются своей функцией в `core/catalog.py`-стиле; если T-07
  уже принята — переиспользовать её `build_catalog()`, это
  предпочтительно, но не обязательно); превью-миниатюра, если
  PNG существуют; поиск по подстроке (клиентский).
- **Страница оружия**: 3D-просмотр GLB (three.js, орбит-контролы),
  кнопки: download / decrypt / unpack / build-scene; выбор оружия
  для запуска стадии (`--weapons <name>` под капотом).
- **Живой лог стадии**: SSE-поток вывода подпроцесса, статус
  (running/done/failed), код возврата.
- **Очередь**: одна активная стадия на сервере; новые запуски
  ставятся в очередь (просто: кнопки блокируются на время работы
  + сообщение).
- Безопасность: bind `127.0.0.1` по умолчанию (`--host` для
  осознанного изменения); при старте генерируется токен в URL
  (`/t/<token>/...`), все мутирующие действия требуют его;
  никаких внешних биндов без явного флага — в логе стартовое
  предупреждение при `--host 0.0.0.0`.

### Нефункциональные

- `wog-dump serve` не блокирует параллельный CLI: транзакции БД
  короткие, гонок не создаёт (SQLite WAL — включить в соединении
  сервера; CLI-режим не меняется).
- Фронтенд без сборки: любые правки UI не требуют npm; статика
  отдаётся FastAPI StaticFiles.

## План реализации

1. `core/webapp/` (пакет в extra): FastAPI-приложение, фабрика
   `create_app(config)`; роуты: `/api/catalog`, `/api/weapons/{name}`,
   `/api/run` (POST — запуск стадии, валидация команды по
   whitelist-таблице стадий и имён оружия — никакой передачи
   произвольных строк в shell), `/api/events` (SSE).
2. Static UI: index (каталог) + weapon page; three.js-вьювер.
3. CLI `serve` в `cli/main.py` (import сервера ленивый — без
   extra команда даёт понятную подсказку `pip install wog-dump[web]`).
4. Токен-аутентификация, очередь, SSE.
5. README + скриншоты.

## Критерии приёмки

- [ ] Каталог отображает реальное состояние runtime/ (сверить с
      выводом CLI на одном наборе)
- [ ] Просмотр GLB ak47 в браузере: вращение/зум, список частей
      (переиспользовать UI-наработки T-04 по возможности)
- [ ] Запуск `build-scene` со страницы: живой лог, результат
      появляется в файловой системе, повторный CLI-запуск видит его
- [ ] Без extra установка даёт понятную ошибку-подсказку
- [ ] `wog-dump serve` и параллельный терминальный `wog-dump info`
      не конфликтуют
- [ ] Токен в URL обязателен: запрос без токена — 404

## Риски и открытые вопросы
