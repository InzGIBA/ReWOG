# T-18: Пайплайн 3D-печати

- **Статус:** не начата
- **Приоритет:** low
- **Оценка:** M
- **Зависимости:** T-03 (экспорт STL из задач 03)
- **Квартал roadmap:** Q4 2027

> Базовая задача T-03 должна быть в статусе «готово» до старта этой.

## Цель

От сцены — к готовым к печати файлам: реальные размеры в
миллиметрах, разбор на части или объединённая раскладка, проверка
и починка не-манифолдных мешей, отчёт о пригодности печати.

```bash
wog-dump print-export ak47                       # все части по STL
wog-dump print-export ak47 --part bolt --real-scale
wog-dump print-export ak47 --merge --spacing 5   # одна раскладка
```

## Контекст: что будет доступно после базовой задачи

- T-03: STL-экспортёр в `core/export.py` (binary STL, `--stl-units`,
  `--stl-per-part`) — базовая геометрия уже умеет уходить в STL.
- `core/scene.py` уже хранит real-world scale (README: сцены
  экспортируются в реальном масштабе) — коэффициенты метры→мм
  известны.
- Чего нет в T-03 и что делает ЭТА задача: диагностика меша
  (манифолдность, замкнутость), авторемонт, осмысленная раскладка
  нескольких частей, отчёт.

## Требования

### Функциональные

- Новая команда `wog-dump print-export <weapon>` (отдельная от
  build-scene: у печати свои решения и параметры; источник —
  decrypted-бандл или готовая сцена, как удобнее по коду T-03).
- `--part <name>` (повторяемый флаг): только выбранные части;
  дефолт — все меши оружия, классифицированные как реальные детали
  (UI/cutaway/VFX отсеиваются тем же `classify_game_object`).
- `--real-scale`: размеры в мм по игровым данным (дефолт: единицы
  STL — мм, масштаб из сцены).
- `--merge`: единый STL с сеточной раскладкой частей, `--spacing MM`
  между частями (дефолт 5 мм).
- Диагностика каждой части: манифолдность (каждое ребро ровно 2
  треугольника), самопересечения (опционально, `--check-intersections`,
  дорого), габариты. Отчёт `print_report.json` + таблица в консоли:
  часть / статус (ok / fixed / warnings) / размеры мм.
- Авторемонт: закрытие дыр (trimesh `fill_holes`/`repair`), удаление
  дегенеративных треугольников, дубликатов вершин; то, что не
  починилось, — статус `warnings` с описанием.

### Нефункциональные

- trimesh — новая зависимость extra `wog-dump[print]` (с numpy);
  манипуляуляции с мешами — через него, свои реализации не писать.
- STL из T-03 используется как есть; эта задача — слой подготовки
  (чистка/починка/раскладка/масштаб) поверх, отдельный модуль
  `core/printprep.py`.

## План реализации

1. `core/printprep.py`: загрузка мешей части из бандла (переиспольз.
   `_mesh_data` из scene.py или OBJ из unpacked/ — выбрать по
   данным T-03), диагностика через trimesh, ремонт, раскладка.
2. Вызов STL-экспортёра T-03 на подготовленных мешах.
3. CLI `cli/print_export.py`, отчёт (JSON + таблица).
4. README: раздел «3D printing» с примерами печати и оговоркой о
   точности масштаба (игровая геометрия ≠ чертёж).

## Критерии приёмки

- [ ] Для 5 разных оружий: все части проходят `--merge`-экспорт и
      открываются в PrusaSlicer/Cura без автоматического ремонта
      (или с минимальными предупреждениями, зафиксировать какие)
- [ ] Отчёт различает ok/fixed/warnings и содержит размеры в мм
- [ ] `--real-scale`: замер распечатанной детали совпадает с
      отчётом в пределах точности принтера (или честно задокументиро-
      вано, что игровой масштаб — приблизительный)
- [ ] `--part` фильтрует и сообщает о несуществующих именах
- [ ] Тесты диагностики/ремонта на синтетических ломаных мешах
      (дырка, дубль-вершины, вырожденный треугольник)

## Тесты

- `tests/unit/test_printprep.py`: синтетические меши (trimesh
  создаёт примитивы; портим их копированием паттернов из
  реальных данных), статусы, раскладка без пересечений
  (bbox-проверка), масштаб.

## Риски и открытые вопросы

- Игровые меши с вырезами/cutaway могут быть неспасаемо дырявыми —
  такие части честно получают warnings, не блокируя остальные.
- Реальный тест «напечатай деталь» — вне CI; критерий проверки
  слайсером достаточно.
