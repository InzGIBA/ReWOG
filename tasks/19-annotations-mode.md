# T-19: Режим аннотаций (образовательный слой)

- **Статус:** готово
- **Приоритет:** medium
- **Оценка:** M
- **Зависимости:** T-04 (HTML-вьювер)
- **Квартал roadmap:** Q4 2027

> Базовая задача T-04 должна быть в статусе «готово» до старта этой.

## Цель

Превратить HTML-вьювер в интерактивную обучающую схему: маркеры на
частях с названиями, боковая панель со списком, подсветка при
наведении/клике. World of Guns — образовательный проект по своей
природе; эта фича делает выгрузку полезной для преподавания и
статей.

```bash
wog-dump build-scene ak47 --viewer --annotate
# viewer.html с маркерами частей и панелью описаний
```

## Контекст: что будет доступно после базовой задачи

- T-04: `core/viewer.py::render_viewer_html(glb, manifest)`,
  вьювер с three.js, списком частей (parts/field_strip из
  `scene.json`) и подсветкой узлов по клику.
- Имена glTF-узлов = имена GameObject-ов; `SceneStats` уже содержит
  списки частей.
- `core/scene.py::_accumulate_bounds()` — расчёт bounding box узлов
  уже есть (используется для камеры) — центр части для маркера
  берётся из него.

## Требования

### Функциональные

- `build-scene --annotate` (работает вместе с `--viewer`; без
  viewer — ошибка с понятным сообщением или явный автодействие:
  включить viewer, выбрать одно поведение и зафиксировать).
- Манифест `scene.json` расширяется секцией `annotations`:
  ```json
  "annotations": [
    {"name": "bolt", "node": "bolt", "center": [x, y, z],
     "group": "parts", "bbox_size": [x, y, z]}
  ]
  ```
  (центр — в координатах glTF-сцены).
- UI: маркеры-точки на частях (спрайты, масштабируемые с дистанцией);
  клик по маркеру = клик по части в списке (подсветка + фокус
  камеры + карточка с названием части и группой parts/field_strip);
  режим «скрыть маркеры» для чистого просмотра.
- Карточка части: название, группа (деталь / field-strip),
  размеры (bbox в мм при реальном масштабе сцены) — контент без
  сети, всё из манифеста.
- Best-effort описания: если в бандле есть текстовые описания
  частей (TextAsset-ы с именами частей — проверить наличие на
  живых данных; в игре есть учебные тексты), подключить в карточку;
  если нет — поле описания просто не показывается. Результат
  проверки зафиксировать в PR.

### Нефункциональные

- Маркеры не рендерятся в сам GLB (сцена не меняется) — аннотации
  живут только в HTML-слое поверх манифеста; GLB остаётся
  девственно чистым для Blender.
- Размер HTML растёт незначительно (маркеры — спрайт-текстура
  одна на все точки).

## План реализации

1. `SceneBuilder`: собрать `annotations` (центры из bounds-прохода,
   группы из списков) в манифест при `--annotate`.
2. Вьювер (T-04): рендер спрайт-маркеров, проецирование 3D→2D,
   связка с существующей подсветкой узлов, карточка, тумблер
   маркеров.
3. Исследование описаний (TextAsset-ы) — при наличии, добавить в
   манифест поле `description`.
4. README: скриншот аннотированного вьювера.

## Критерии приёмки

- [ ] `--viewer --annotate` для ak47: маркеры на всех частях,
      клик — подсветка + карточка с названием и группой
- [ ] GLB в этой же папке не отличается от собранного без
      `--annotate` (побайтово)
- [ ] Манифест содержит annotations для каждого узла из списков
      parts/field_strip; узлы вне списков аннотаций не получают
- [ ] Тумблер маркеров работает; вьювер остаётся офлайн
      (без сетевых запросов — тест T-04 продолжает проходить)
- [ ] Юнит-тест генерации annotations (центры по фиксированному
      синтетическому дереву)

## Тесты

## Риски и открытые вопросы

- На мелких частях маркеры сливаются: кластеризация при отдалении
  камеры — nice to have, не блокер; зафиксировать как известное
  ограничение в PR, если не успевается.
