# T-21: Blender-аддон

- **Статус:** готово
- **Приоритет:** medium
- **Оценка:** M
- **Зависимости:** T-07 (команда catalog с JSON-выводом)
- **Квартал roadmap:** Q4 2027

> Базовая задача T-07 должна быть в статусе «готово» до старта
> этой: аддон потребляет её стабильный JSON-контракт
> (`wog-dump.catalog/1`).

## Цель

Нативное расширение Blender: панель WOG Dump в сайдбаре — список
оружия со статусами, кнопка «импорт сцены» прямо в открытый .blend,
без терминала вообще. Установка из .zip через систему расширений
Blender 4.2+ (blender_manifest.toml).

## Контекст: что будет доступно после базовой задачи

- T-07: `wog-dump catalog --json` — машиночитаемый список оружий
  со статусами стадий и схемой `wog-dump.catalog/1` — интерфейс
  между аддоном и тулкитом.
- `runtime/scenes/<weapon>/<weapon>.glb` + `blender_setup.py` —
  то, что импортируем (Blender сам умеет glTF-импорт; setup-скрипт
  сцены — опционально для полного обустройства сцены).
- Ключевое ограничение: аддон НЕ содержит Python-зависимостей
  тулкита (UnityPy и пр. не ставятся в окружение Blender) —
  работает ТОЛЬКО через subprocess-вызовы установленного
  `wog-dump` CLI. Это принципиальное архитектурное решение.

## Требования

### Функциональные

- Пакет расширения Blender 4.2+ (`blender_manifest.toml`,
  extensions-платформа; .zip ставится через Preferences →
  Extensions → Install from Disk).
- Панель «WOG Dump» (N-panel вкладка): список оружия из
  `wog-dump catalog --json` (колонки: имя, статус сцены ✓/—),
  поле фильтра, кнопка Refresh.
- Кнопка «Import scene»: для выбранного оружия — если GLB сцены
  нет, сначала запускает `wog-dump build-scene <weapon>`
  (терминальный вывод пишется в окно консоли Blender), затем
  импортирует GLB (`bpy.ops.import_scene.gltf`) в текущий .blend.
- Кнопка «Build missing» для выделенных: build-scene по списку
  (последовательно, с сообщениями о прогрессе).
- Настройки аддона: путь к `wog-dump` (дефолт — `shutil.which`,
  в настройках переопределяется; неверный путь — понятная ошибка
  с инструкцией `pip install wog-dump`).
- Всё состояние — опрос CLI; аддон ничего не знает о БД/путях
  тулкита напрямую (единственная точка связи — catalog JSON и
  subprocess-команды).

### Нефункциональные

- Репозиторий аддона: подпапка `blender-addon/` в этом же репо
  (один PR-цикл, общий CHANGELOG; релизный артефакт .zip собирается
  скриптом `scripts/build_addon.py` — копит файлы, валидирует
  манифест).
- Проверка схемы: аддон валидирует `schema == "wog-dump.catalog/1"`
  и при несовпадении даёт сообщение «обновите wog-dump», а не
  падает.
- Никакой сетевой активности самого аддона (сеть — только через
  вызываемый CLI).

## План реализации

1. Каркас расширения: манифест, панель, настройки, подпроцесс-
   обёртка (`run_wog(args) -> (code, stdout, stderr)`).
2. Парсер catalog JSON + UI-список (UIList) + фильтр.
3. Import scene / Build missing: последовательность подпроцессов,
   сообщения в консоль Blender, импорт GLB.
4. `scripts/build_addon.py`, CI-шаг сборки zip (артефакт к релизу).
5. README-раздел: установка, скриншоты, ограничение «нужен
   установленный wog-dump».

## Критерии приёмки

- [ ] .zip устанавливается в Blender 4.2+ без ошибок манифеста
- [ ] Панель показывает реальный каталог (сверить с `catalog`
      в терминале на одном наборе); фильтр работает
- [ ] «Import scene» для оружия без сцены: запускает build-scene,
      затем импортирует модель в текущий .blend
- [ ] Без установленного `wog-dump` — понятная ошибка и путь
      исправления
- [ ] Изменение JSON-схемы catalog (тест с schema/2) — аддон
      сообщает «обновите тулкит», не падает
- [ ] Скрипт сборки .zip работает в CI; артефакт приложен к
      релизу

## Тесты

- Юнит-тесты Python-части аддона (без Blender: функции парсинга
  JSON, обёртка подпроцесса на моках) — `tests/unit/test_addon.py`
  (модули аддона импортируются без `bpy` — держать парсер/обёртку
  в отдельных от UI файлах).
- Blender-часть — ручной чек-лист на 4.2 и 4.5 LTS (шаги в PR).

## Риски и открытые вопросы

- API Blender 4.x меняется между минорными версиями — минимальный
  используемый API-поверхностный слой (panel, UIList, operator,
  preferences); зафиксировать поддержку «4.2 и новее» в манифесте.
- Импорт больших GLB (100+ МБ) внутри UI-потока подвешивает
  Blender — импорт через стандартный оператор с «Use running in
  background» невозможен; оставить синхронный импорт (Blender
  сам показывает прогресс), отметить в доке.
